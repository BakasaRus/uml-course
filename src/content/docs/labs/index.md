системы. Начиная с ЛР 3, храните UML-диаграммы в одном проекте Visual Paradigm
Community Edition и обновляйте ранее созданные представления, если новое

## Общие критерии

Перед выполнением работы можно использовать [практикум UML с разборами](/notation/exercises). Он помогает проверить базовую семантику и не является дополнительной частью отчёта.

- Каждый артефакт отвечает на конкретный вопрос о системе и использует термины
  из словаря предметной области.
- Требование, правило, вариант использования, сценарий, предметный объект,
  технический элемент и сообщение должны быть согласованы там, где они
  описывают одну ситуацию.
- Не добавляйте на диаграмму детали реализации, если они не отвечают на её
  вопрос; не маскируйте архитектурное решение под требование.
- В отчёте указывайте ФИО, группу, номер лабораторной работы и экспортированные
  диаграммы, а не скриншоты редактора.

Лекция об архитектурных представлениях C4 завершает эту цепочку и используется
для итоговой проверки трассируемости. Отдельная лабораторная по C4 не требуется:
C4 не заменяет UML-артефакты, созданные в ЛР 3–7.
